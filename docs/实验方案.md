# 模块验收与实验方案

对应题目：**面向混合注意力模型的前缀缓存管理模块设计与实现**。实验服务于模块验收、问题归因与适用边界说明。

## 已完成的初步实验

使用 Qwen3.5-0.8B 和 vLLM 0.30.0，完成 19 次独立运行、2432 个成功请求。覆盖热点加一次性扫描、混合文档热度和缓存充足三种场景；原版与 `reuse2` 共 9 组对照，另有一次原版同种子重复。

原始计时为串行、CUDA 同步后的离线 `generate` 调用耗时。正式测量排除启动、预热、缓存重置和结果落盘，诊断观察器关闭。KV 配额分别为 128MiB、256MiB 和 4096MiB，生成长度为 32 或 1 token。

热点场景存在复用收益，混合文档收益方向不一致，缓存充足时两策略命中量相同。一次热点短输出 p95 约退化 20.3%，原因待进一步定位。完整数值和测量口径见[公开结果](../data/public/hybrid-prefix-retention/server-20260930/README.md)。

这些结果用于确定模块方向。正式模块完成后，按以下要求验收。

## 对照对象

- 原版组：锁定版本的 vLLM，启用前缀缓存，说明已有相关配置及调参过程。
- 基础组：基于实际复用次数的 `reuse2`，保留其配置与行为作为参照。
- 模块组：正式管理模块及其候选保留策略，明确依据、变化与附加开销。

每组使用相同权重、请求、生成参数、硬件和缓存配额。已有 eager 串行初步数据单独保留；正式服务配置与测量结果另行登记。

## 必要场景

| 场景 | 检查目的 |
| --- | --- |
| 热点内容与一次性内容混合 | 检查热点被挤出后的复用损失与保留效果 |
| 文档热度不均、共享文档但问题不同 | 检查更一般的复用分布及策略失效情况 |
| 相同请求集、缓存容量充足 | 检查没有保留收益时的附加开销 |
| 无共享或无复用请求 | 检查新请求、冷请求开销 |

另按模块实现检查缓存重置、连续运行和对象再分配路径。并发、共享前缀分叉或多轮续写测试根据新增机制选择，记录各自目的。

公开文档提供真实文本，访问顺序和热度分布仍由生成器构造。保存来源版本、文档 ID、请求哈希、输入长度、种子和到达顺序。

## 指标与口径

1. **输入 token 命中**：使用引擎请求级计数，汇总所有请求，并与必要的诊断事件交叉核对。
2. **输入计算与重算**：明确执行计数来源；首次出现、淘汰后重算与边界对齐损失分别关联事件证据，尚未实现的计数标为待实现。
3. **离线耗时**：同步后的生成调用耗时，报告总量、中位数和 p95；短输出只能辅助观察输入计算阶段的影响。
4. **在线指标**：服务模式下单独测流式首 token 时间、生成间隔和吞吐，注明流事件判断规则、到达率、并发和输出长度。
5. **管理开销**：候选扫描数量、保留信息条数、选择耗时及冷请求表现。
6. **正确性与稳定性**：输出 token 对照、运行完成率、重置后记录清理和连续运行行为。

小样本结果注明请求数和独立轮次数。p99 等尾部指标须说明样本支持情况；百分位算法固定并记录。

## 对照与保存约定

- 固定版本、权重、配置和请求序列；原版与候选成对比较。
- 预热与正式计时分开，诊断与性能测量分开。
- 正式性能比较先检查原版重复波动，交替运行顺序并完成必要重复；初步的一组原版重复仅说明当次波动。
- 同时保存全请求结果、冷请求诊断及尾部异常，按独立轮次报告分布和适用边界。
- 图表由保存的数据和分析脚本生成；部分运行、失败启动和完整运行分别登记。
- 对有针对性的异常补实验，围绕模块问题安排资源与工作量。
