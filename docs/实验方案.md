# 初步实验方案

## 对照组

主要 Baseline 为启用 Prefix Cache 的原版 vLLM。改进组只改变一项缓存管理策略，其他设置保持一致。LFU 等策略视时间作为补充对照，不作为最低交付条件。

## 工作负载

1. **无共享请求**：检查策略开销与退化风险。
2. **固定共享前缀**：检查 System Prompt 等重复前缀能否被复用。
3. **多轮对话**：检查多个会话交替访问时的缓存表现。

在请求集里记录 Token 长度、到达顺序、并发度、前缀重复比例和随机种子。先用可控的合成请求定位行为，随后加入真实文本或公开请求轨迹验证。合成工作负载不称为真实生产负载。

## 核心指标

- 前缀命中 Token、实际重新 Prefill 的 Token 数。
- TTFT 的中位数和 P95、请求吞吐或生成 Token 吞吐。
- KV Cache 容量及占用；必要时观察 GPU 总显存。

P99、最大并发等指标只有在样本量和环境允许时再报告。各指标的采集来源和计算口径在实现时固定并记录。

## 公平性与复现

- 固定模型权重、推理参数、vLLM 版本、GPU、显存预算和请求序列。
- 预热与正式测量分开；每组重复运行并保存原始结果。
- 分别报告有利场景和不利场景，不以单个最佳数字代表普遍性能。
- 保存运行配置与代码版本，确保图表可以从原始记录重建。

当前尚无对比结果，文档中的实验安排不是性能承诺。
