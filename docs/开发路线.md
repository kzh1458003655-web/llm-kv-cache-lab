# 开发路线

对应题目：**面向混合注意力模型的前缀缓存管理模块设计与实现**。完整范围与完成标准见[毕业设计任务书](毕业设计任务书.md)。

## 已完成：原型与初步实验

- [x] 在真实 vLLM 0.30.0 上运行 Qwen3.5-0.8B 混合模型。
- [x] 实现缓存组配置、命中、登记与哈希移除的诊断观察器。
- [x] 实现可切换的 `reuse2` 保留原型及原生回退路径。
- [x] 完成固定负载、独立进程运行、结果分析与公开数据导出。
- [x] 完成 19 次运行、2432 请求的初步实验，记录收益、无收益及尾延迟退化。
- [x] 保存环境、版本、请求哈希和输出哈希，公开代码与测量数据。

已有原型支持正式模块开发；其输出哈希对照属于初步检查，完整模块验收仍需开展。

## 阶段一：模块设计与代码梳理（第 1—2 周）

- [ ] 画出前缀查找、登记、回收、重置的数据路径及缓存组关系。
- [ ] 设计引擎适配、策略接口、保留信息和观测接口。
- [ ] 明确配置、版本检查、适用路径与开销上限。

交付：模块设计、接口说明和对象生命周期图。

## 阶段二：正式模块实现（第 3—5 周）

- [ ] 将现有运行时原型整理为有配置和版本说明的正式集成方式。
- [ ] 实现统一的原版/候选切换，完善淘汰、重置及再分配时的记录清理。
- [ ] 基于复用次数策略处理过期保留与候选选择开销。
- [ ] 完成缓存安全、生命周期和连续运行的必要检查。

交付：可运行模块、配置、复现步骤及正确性记录。

## 阶段三：策略整合与问题解决（第 6—8 周）

- [ ] 参考 Marconi 的复用可能性、计算收益与内存成本，完善至少一种候选保留策略。
- [ ] 记录引用思路、具体实现及与原论文的差异。
- [ ] 完成热点、混合热度、缓存充足与无复用开销检查。
- [ ] 定位尾延迟退化与冷请求开销，区分机制原因和环境波动。

交付：策略说明、对照数据和问题归因记录。

## 阶段四：收尾与论文（第 9—12 周）

- [ ] 修复发现的问题，补充有明确目的的容量或并发对照。
- [ ] 整理适用边界、附加开销、限制及复现材料。
- [ ] 按展示需要制作缓存时间线或策略对比页面。
- [ ] 完成毕业论文、源码与数据说明、答辩材料。

交付：稳定版本与完整毕业设计材料。

## 完成标准

真实混合模型上的管理模块、可切换的保留策略、正确的对象生命周期处理、受控的附加开销、必要场景的可复现对照和完整说明。

性能结果按实际测量呈现；评测围绕模块验收与具体问题展开。检查点位置、队列感知及更大模型等扩展根据完成情况选择。
