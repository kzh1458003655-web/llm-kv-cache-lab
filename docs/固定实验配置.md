## 主模型固定为 Qwen3.5-9B

后续正式混合模型实验采用 **Qwen/Qwen3.5-9B、纯文本模式、BF16、关闭权重量化与推测解码**。固定权重 revision 为：

```text
c202236235762e1c871ad0ccb60c8ee5ba337b9a
```

下载时使用该 revision，并核对文件哈希。vLLM 0.30.0、Torch 2.13.0、Transformers 5.17.0 作为当前固定环境。后续策略比较使用同一模型、分词器、依赖与硬件；必要的配置变更单独记录版本和原因。

## 为什么选择 3.5

- Qwen3.5-9B 有公开权重，包含本课题所需的混合结构，可以在本地 vLLM 中观测和修改缓存管理。
- [Qwen3.7-Max 官方介绍](https://qwen.ai/blog?id=qwen3.7&locale=en)说明其为闭源模型，通过 API 提供服务。本课题需要修改推理引擎内的缓存流程。
- [官方 Qwen 开源仓库](https://github.com/QwenLM/Qwen3.8)列出较新的 Qwen3.8-27B 等版本；截至本次核对，未查到官方 Qwen3.8-9B。
- 正式实验以结构适合、权重可获得、版本可固定和结果可复现为选择依据。较新模型可放入相关工作讨论。

## 9B 上需要补做的关键对照

1. 先检查前缀命中与检查点边界，记录共享长度和实际复用长度；充足缓存下排除容量淘汰。
2. 重跑热点加一次性请求、混合文档热度和缓存充足的原版/候选对照。
3. 正式使用在线流式请求，测首 token 时间、生成间隔、吞吐与失败数；输入目标 2048/4096 token，输出 128 token，客户端并发上限 8/16，每轮 512 请求。
4. 正式论文阶段代表配置目标为 5 组独立的成对对照；开题前按[补测清单](../configs/nineb-opening-plan.json)先完成热点、混合各 3 组，以及原版同一固定请求集独立运行 3 次。同步记录无复用对照与尾延迟。
5. 重新按 9B 分词器生成固定请求文件，并保存相同种子和到达时间表。公开文本来源沿用已锁定的完整 LooGLE 数据。

512 个请求属于同一轮工作负载，统计时按独立运行汇总。并发上限和实际活跃请求数分别记录。

## 一次性校准后固定的内容

实际 GPU、驱动、CUDA graph 模式、适用的原生检查点配置、到达率与缓存字节配额，需要在 9B 首次预检中核定。校准记录全部保留，在正式策略对照前冻结这些值。

小、中、大缓存预算是实验变量，按固定三档运行。容量须结合 9B 的缓存组和活跃请求空间选择，记录工作集与缓存容量的比例。既有 0.8B 的 128MiB/256MiB 预算不直接沿用。

普通全注意力模型若用于检查点行为的参照，应登记为单独的机制对照，并独立保存结果。主模型始终为 9B。
