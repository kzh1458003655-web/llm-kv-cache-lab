# 设计概览

## 目标与边界

项目基于真实推理引擎，研究已经计算完成、可供后续请求复用的 KV Cache 如何被记录和管理。运行中请求占用的 KV Block 与可回收的缓存块在语义上不同；策略改动不能破坏运行中请求的正确性。

## 模块

| 模块 | 职责 | 当前状态 |
| --- | --- | --- |
| 推理服务适配 | 启动真实模型，连接 vLLM 的请求与缓存管理流程 | 待实现 |
| 缓存事件采集 | 输出分配、释放、命中、淘汰等事件 | 仅有事件格式 |
| 策略接口 | 在同一引擎版本下切换原版与改进策略 | 待实现 |
| 工作负载回放 | 固定请求序列、并发度、前缀比例和随机种子 | 待实现 |
| 指标统计 | 汇总命中 Token、TTFT、吞吐与显存数据 | 待实现 |
| Web 页面 | 交互推理、事件回放、实验对比 | 待实现 |

## 数据流

请求集 → vLLM 推理服务 → 缓存事件与请求级指标 → 实验记录 → 统计结果 / 页面展示。

`CacheEvent` 是内部事件格式，不等同于 vLLM 原生指标。接入时应优先复用引擎已经提供的请求级统计，增加必要的 Block 级事件；不能仅凭模拟事件宣称真实引擎已完成优化。

## 重要约束

- 原版和改进版使用相同的模型、vLLM 版本、硬件、KV Cache 预算和请求序列。
- 对策略修改进行输出正确性与服务稳定性检查。
- 未实际运行的模块不在 README 中标为完成。
- Web 图示只表达真实采集到的事件及其逻辑关系，不伪称 GPU 物理地址视图。
