# 设计概览

对应题目：**面向混合注意力模型的前缀缓存管理模块设计与实现**。正式范围见[毕业设计任务书](毕业设计任务书.md)。

## 目标与实现对象

在 vLLM 中实现一个管理模块，决定可复用缓存的保留优先级，并接入原生回收流程。混合模型的前缀复用同时涉及注意力 KV、状态检查点和缓存组匹配；策略需要遵守锁定版本已有的对象生命周期与可复用边界。

主体围绕保留与淘汰、策略切换、保留信息维护和行为观测展开。检查点位置、队列感知等内容根据具体问题作为扩展。

## 模块与当前状态

| 部分 | 职责 | 当前状态 |
| --- | --- | --- |
| 引擎适配 | 连接前缀查找、空闲块回收、哈希移除与缓存重置 | vLLM 0.30.0 原型已跑通；正式适配层待整理 |
| 策略接口 | 原版与候选策略切换，配置与适用性检查 | 已有原型开关；统一接口待实现 |

| 缓存组处理 | 记录对象所属组，保持原生匹配与回收约束 | 已有组级诊断；跨组保留策略及完整检查待完成 |
| 行为观测 | 输出命中、缓存登记与哈希移除事件 | 真实诊断观察器已实现；规范化汇总待完善 |

| 辅助展示 | 缓存时间线与策略对比 | 待实现，可按答辩展示需要选择 |

## 已有原型的介入位置

1. `KVCacheManager.get_computed_blocks`：记录真实命中的缓存哈希，累计复用次数。
2. `BlockPool.get_new_blocks`：检查有限数量的空闲块，优先安排低复用对象参与原生回收。
3. 哈希移除与前缀缓存重置：清理对应的保留信息。
4. 原生分配路径：继续完成引用计数、淘汰通知和哈希移除等动作。

当前 `reuse2` 在符合条件的分配路径中最多检查 32 个候选空闲块，复用次数计数上限为 2。不符合原型适用条件时直接沿用原生路径。正式模块需要将这些常量、条件和信息生命周期整理成明确接口。

## 数据流

固定请求集 → vLLM 前缀查找 → 保留信息更新 → 候选选择 → 原生分配与回收 → 请求级记录 / 诊断事件 → 分析与展示。

计时模式保存必要的请求级结果；诊断模式额外记录块级事件。诊断日志可能产生额外开销，两种模式分别运行并注明。

## 约束与验收重点

- 只选择引擎允许回收的空闲对象，保持引用计数、空块和缓存组匹配规则正确。
- 保留信息随哈希移除、重置与对象再分配清理；记录大小、候选扫描和执行开销均有上限。
- 原版与候选策略使用相同模型、软件版本、缓存配额、请求序列和生成配置。
- 分别检查模块正确性、附加开销和策略效果；保留有利、无收益与退化结果。
- `CacheEvent` 是内部格式，原始观察器事件与该格式之间的映射需显式说明。
- 当前诊断中的哈希移除事件有调用语境，不能直接把所有移除都计为容量淘汰；淘汰后重算需要进一步关联请求与历史事件。
