# 单卡租机实验包

目标：扩大已经跑通的混合模型缓存保留对照，检查效果是否随文档和重复运行稳定。模型为固定版本 Qwen3.5-0.8B，策略为已有的有限扫描 reuse2 原型；不是完整复现 Marconi。

## 机器

单卡 RTX 4090D 24GB 足够。Linux、可联网、Python 3.12、建议 PyTorch/CUDA 镜像；至少 20GB 可用磁盘。优先使用已有 PyTorch 镜像，安装可能占用租期，不能保证一小时完成全部轮次。系统显示的 CUDA 上限不等于已安装可用的 PyTorch 环境。

## 运行

上传本机准备的 `hybrid-server-ready.tar` 并解包。实验包已包含模型、完整数据源和固定请求，不需要租机后再下载模型或数据。模型及数据按各自许可使用，不进入 Git 仓库。

```bash
tar -xf hybrid-server-ready.tar
cd hybrid-server-ready
python3 scripts/verify_server_bundle.py
bash server-kit/setup.sh
.venv-server/bin/python scripts/run_server_round.py --model model --prepared prepared --output data/runs/server-round --minutes 45 --repeats 5
tar -czf server-results.tar.gz data/runs/server-round
```

如果镜像 Python 不是 3.12，先选正确解释器，再创建虚拟环境。安装出错时保留日志，不在租期内尝试源码编译 vLLM。入口脚本只结束自己创建的实验进程，**不会关闭实例或停止计费**；下载结果后在平台停止实例。

## 固定规模

用于开题判断时，可增加 `--decision-screen --repeats 3`。计划共 23 次独立运行：三场景各三次成对对照（18 次）、热点负载原版同种子重复一次，以及热点和混合负载各一次只生成 1 token 的成对检查（4 次）。顺序优先覆盖三场景、原版波动和短输出，再增加轮次；预算不足会保留实际完成的覆盖情况。短输出计时仍是离线 generate 调用，不是线上 TTFT。

- 热点加扫描：128 请求，KV 缓存预算 128MiB。
- Zipf 文档混合：128 请求，KV 缓存预算 256MiB。
- 相同混合负载的大缓存对照：128 请求，预算 4096MiB，覆盖选中文档的缓存工作集；实际是否无淘汰需结合命中数据判断。
- 每种场景对照原版和 reuse2，最多 5 次独立进程重启；共最多 3840 请求。奇数轮反转运行顺序，每轮固定种子，两种策略用同一请求文件。
- 每个请求生成 32 token；预热两次后清除缓存和策略计数，预热不入统计。
- 每个进程最长 3 分钟；预算不足时停止开启新对照，已完成和失败记录均保留。45 分钟是运行上限，不含上传和安装，应根据剩余租期调短。

## 保存与解释

每次请求保存输入 token、缓存命中 token、输出 token 哈希、完整 generate 调用耗时；计时不含单请求落盘。测量不启用之前逐事件写文件的观察器。日志和每轮 summary 保存版本、设备与失败状态；analysis.json 给出逐轮数据、成对缓存增益和耗时变化。

这是串行离线实验，耗时不是流式 TTFT，也不是线上并发吞吐。小缓存预算用于人为控制压力，不能宣称 24GB 卡默认配置就有同样问题。请求来自公开 LooGLE 文档截断及人工安排的到达顺序，不是生产流量或原始问答评测。重复请求相关，应看独立轮次的一致性，不能把 3840 个请求当成 3840 次独立实验。

公开范围：代码、固定种子、请求哈希、来源信息、审核后的逐请求测量和分析。完整文档、提示和权重只存在上传实验包；不公开 SSH 信息、密钥、平台令牌或未审核的服务器日志。
