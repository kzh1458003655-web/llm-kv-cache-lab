# 混合模型缓存保留：服务器初步实验

## 结论

可以据此确定工程型本科毕设的模块范围：**混合注意力模型前缀缓存保留管理模块**。机制确实能保住更多热点前缀，具备可实现、可验证的工程问题；现有结果不足以宣称普遍性能提升、新策略创新或论文发表能力。

建议题目：《基于 vLLM 的混合注意力模型前缀缓存保留管理模块设计与实现》。下一阶段围绕一个模块做策略接口、缓存组一致性、保留信息生命周期、命中及淘汰观测；实验框架用于验收和解释适用边界。reuse2 是已有思路的原型基线，不是完整 Marconi 复现。

## 环境与覆盖

- 时间：2026-09-30，台北时区。服务器实际报告 NVIDIA GeForce RTX 4080 SUPER，约 32GB 显存；不是 5090D 的结果。
- 驱动 580.76.05；固定模型 Qwen3.5-0.8B，模型及数据 revision/哈希见 runtime-profile 和此前固定负载审核目录。
- vLLM 0.30.0、Torch 2.13.0、Transformers 5.17.0；BF16、eager、单请求串行、上下文上限 2048。逐事件观察器关闭。
- 19 次完整的独立进程运行，每次 128 请求，**2432/2432 成功**。包含 9 组 A/B：三种 32-token 场景各一组，热点和混合的 1-token 场景各三组；另有一次原版同种子重复。
- 所有 A/B 逐请求输入哈希、输入 token 数及 manifest 一致，输出 token 哈希 **1152/1152 匹配**；原版重复输出也匹配 128/128。它们是正确性烟测，不是全面正确性证明。
- 首次运行因 180 秒进程上限包含约 93 秒首次编译而中断，71 条完成记录单独保留在 initial-timeout，不参与策略对照。后续使用编译缓存完成正式运行。
- 首先完成三种场景、原版重复及短输出；租期限制下，32-token 场景没有完成计划中额外的两轮。短输出各完成三个不同种子，两策略种子对应相同请求。

## 32-token 输出结果

变化为 `(reuse2 / 原版 - 1)`，负数表示耗时降低。缓存预算是人为设置的 KV 配额，不是整卡显存。

| 场景 | KV 预算 | 原版命中 token | reuse2 命中 token | 原版总请求耗时 | reuse2 总请求耗时 | 耗时变化 |
|---|---:|---:|---:|---:|---:|---:|
| 热点加一次性扫描 | 128MiB | 52,224 | 69,632 | 108.078s | 103.679s | -4.07% |
| Zipf 混合文档 | 256MiB | 30,464 | 36,992 | 104.459s | 105.765s | +1.25% |
| 相同混合请求、大缓存 | 4096MiB | 82,688 | 82,688 | 103.180s | 103.957s | +0.75% |

原版热点请求的第二次独立运行耗时为 108.409s，相对第一次 +0.31%，命中 token 完全一致。这只有一组 A/A，不能视为所有配置的噪声上限或完整置信区间。

## 1-token 输出结果

短输出用于减少 decode 对总耗时的掩盖，仍然不是流式 TTFT。

| 场景 | 种子轮次 | 命中 token 增量 | 总请求耗时变化 |
|---|---:|---:|---:|
| 热点扫描 | 0 | +17,408 | -8.77% |
| 热点扫描 | 1 | +17,408 | -10.27% |
| 热点扫描 | 2 | +16,320 | -3.70% |
| 混合文档 | 0 | +6,528 | -5.24% |
| 混合文档 | 1 | +1,088 | +1.25% |
| 混合文档 | 2 | +2,176 | -1.55% |

热点短输出三轮总耗时均降低，中位变化 -8.77%；混合短输出收益小且方向不一致。**第三轮热点短输出 p95 从 126.04ms 升至 151.63ms，约恶化 20.3%**。该异常没有完成归因，不能把总耗时收益包装成尾延迟全面改善。

本分析的 p95 使用排序后索引 `floor(0.95*(n-1))` 的下侧样本值，不与插值百分位混用。总请求耗时是逐请求、CUDA 同步后的 generate 调用时间之和；不含模型启动、预热、缓存重置和逐条结果落盘。wall_ms 另包含循环与落盘开销。

## 能支持的判断

1. 有受控缓存压力时的保留空间，原型能够改变实际复用，且热点扫描收益在不同种子下存在。
2. 大缓存原版已达到相同命中，不能称最新版 vLLM 普遍有缺陷。
3. 混合文档上的效果有限，尾延迟也存在退化信号。后续工程应处理策略失效、过期保留和开销边界，不能预设其原因已经确定。
4. 这些证据支持可交付、可复现的缓存模块毕设；不支持通用加速、生产收益或 CCF 论文创新已经成立。

LooGLE 提供真实公开文档，但截断、Zipf 分布和热点/扫描顺序均为人为生成；没有生产 trace、并发排队、在线吞吐、流式 TTFT、默认 CUDA graph 配置或更大模型验证。只生成 1 token 的情况也不是完整用户交互负载。现阶段不再用无止境筛方向替代模块实现；适用边界应作为后续验收内容。
