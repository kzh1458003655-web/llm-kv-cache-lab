## 输出一致性与证据边界

原版同输入的三次 A/A 重跑之间，512 个输出哈希均一致；它们各自与最早原版运行有77/512不同。候选在线对照的差异仍需进一步归因，不能依据原版也有差异就排除候选错误。

串行64请求的原版重复、原版与候选对照均为0哈希差异；候选实际重排139次。边界12请求的成对输出一致，无复用512请求对照也全部一致。这些是限定场景的检查，不能当作全面正确性认证。所有性能数值属于探索性测量，尚未消除在线输出差异的影响。

三个MambaSpec组和一个FullAttentionSpec组在本次实际配置下均为528 token块；527/528/529及1055/1056/1057的边界请求展示了取整匹配。中等缓存64请求诊断出现哈希回收和再次登记，8GiB的同一短诊断没有回收。回收事件不是精确重算token数，8GiB完整512请求也不能仅凭短诊断称为无淘汰。

两类主要负载各三个成对种子；512个请求不等于512次独立重复。报告各组方向和范围，不宣称可靠的总体置信区间。p99仅作诊断。公开LooGLE文档的截断输入与人工访问次序不是生产trace，不评价问答质量。

本轮是过载压力重放：客户端与服务器均可能排队。TTFT为发送到首个生成token-ID流式块；`arrival_to_first_token_ms`包含从计划到达到发送的等待，须同时查看。吞吐为此到达率下的实际吞吐，不是最大服务能力。策略CPU计数仅覆盖空闲块选择阶段，不是完整策略或服务器CPU开销。
